# hugill-8121.github.io

纯静态的 GitHub Pages 单页博客：首页、文章详情、在线写文章、资源管理都在同一个页面（`index.html`）里完成，交互逻辑拆在 `assets/js/app/` 下按领域分文件，所有写操作用 GitHub Token 通过 GitHub API 直接提交回本仓库，不需要任何后端。

- 线上地址：<https://hugill-8121.github.io/>
- 构建方式：GitHub Pages（源 `main` 分支根目录，`legacy` 构建；根目录的 `index.html` 优先于 Jekyll 主题页）
- 浏览器要求：支持原生 ES Module 的现代浏览器

## 设计原则

- **可移植**：代码里不写死仓库名、站点名。`owner` / `repo` / `branch` / 站点标题 / 图标全部来自 `blog-config.json`，fork 之后改配置即可复用。
- **零后端**：读用 GitHub Pages 静态文件 + GitHub API，写用浏览器里保存的 Token。
- **分类 ≠ 目录**：分类（group）只决定首页卡片分组，不允许含 `/`；文章的真实位置由「文件目录 + 标题」决定，即 `blog/<文件目录>/<标题>.md`，目录可多级、留空时取分类名。
- **写操作原子化**：一次保存或一次“提交资源”都是一整批 blob → tree → commit → 更新 ref，不会留下半成品中间提交。
- **先登记，后提交**：编辑页里的移动、重命名、删除、上传都只进内存中的待提交队列，最后点一次按钮才真正提交。

## 目录结构

```
.
├─ index.html            单页应用：只有页面结构 + 一个入口 <script type="module" src="./assets/js/app/main.js">
├─ blog-config.json      站点与文章元数据：标题、简介、图标、分类、uuid、路径、tags、hidden
├─ _config.yaml          Jekyll 主题配置（仅作为 Pages 兜底）
├─ blog/                 文章正文 Markdown（按目录分层）
├─ media/                文章引用的图片等资源文件（对应页面右侧资源栏）
├─ assets/
│  ├─ css/style.css      全部样式
│  ├─ images/favicon.svg 默认站点图标
│  └─ js/
│     ├─ github-api.js   Octokit 封装 + CommitBatch 原子提交 + 文件读取
│     ├─ blog-config.js  配置读取、base64 解码等工具
│     ├─ blog-utils.js   Markdown 渲染、容器切换等
│     └─ app/            单页应用的业务模块（入口 main.js）
│        ├─ main.js           启动编排：读配置、校验登录、渲染首页/详情、绑事件
│        ├─ state.js          全部共享可变状态（state 对象）与仓库配置 config
│        ├─ dom.js            DOM 引用表，页面结构改这里
│        ├─ utils.js          路径编码、localStorage、Token、toast、favicon
│        ├─ auth.js           登录校验、登录/登出 UI、Token 失效降级匿名
│        ├─ list.js           首页列表：配置、commit 缓存、标签云、月份、卡片
│        ├─ show.js           文章详情：定位文章、正文、最新 commit
│        ├─ editor.js         编辑区：标签页、表单快照/脏标记、标签 chip、分类目录候选
│        ├─ file-tree.js      左侧文件栏（blog 目录树）
│        ├─ repo-tree.js      仓库树抓取与缓存（资源栏、文件栏共用）
│        ├─ resource-tree.js  资源栏视图：树渲染、拖拽移动/重命名、右键菜单、搜索
│        ├─ resource-queue.js 资源待提交队列：上传/新建/删除登记与一次提交
```

外部依赖全部走 CDN，并锁定版本：Octokit（`esm.sh` bundle 固定版）、Showdown（Markdown → HTML）、DOMPurify（HTML 消毒）、Prism（代码高亮）、MathJax（公式）、Font Awesome、jQuery。

> 直接用 `file://` 打开 `index.html` 时，配置读取和 Token 记忆会受同源策略限制；本地调试建议起一个静态服务（如 `python -m http.server 8080`）。

## 功能模块

### 页头

- 站点标题、简介、标签页图标：初始为 `assets/images/favicon.svg`，`blog-config.json` 配了 `web_icon` 就以它为准；登录成功后换成当前 GitHub 用户头像（`?s=64`），头像加载失败或登出时回到站点图标。
- 右上角头像下拉菜单：
  - **登录 / 登出**：登录后 Token 存在浏览器 `localStorage`，登出即清除，新增/编辑/资源提交等写能力随之失效；
  - **刷新**：重新拉取配置与仓库文件树；
  - **查询 API 状态**：弹窗展示用户名、Token 权限范围，以及 Core / Search / GraphQL 的剩余次数与重置时间；
  - **新增 blog**：直接进入新建文章编辑页。

### 首页（文章列表）

- **标签云**：列出配置中出现过的全部标签，支持多选过滤（命中任一选中标签即显示）；已隐藏的文章不参与统计。
- **月份竖栏**：按月份列出文章数量，支持勾选多个月份，底部还有起止月份范围选择与“重置”。
- **文章卡片**：按 `blog-config.json` 的分类分组展示，卡片上显示标题、标签，以及该文章的最近一次提交人 / 时间 / commit 信息（批量查询；匿名接口限流时这几项可能为空，属正常现象）。
- 配置里 `hidden: true` 的文章不出现在首页。

### 文章详情页

- 大写标题、标签列表、编辑按钮。
- 提交信息面板：作者、提交时间、提交说明、可点击的 commit SHA。
- 正文 Markdown 渲染（Showdown 转换 + DOMPurify 消毒 + Prism 代码高亮 + MathJax 公式）。
- 地址带 `fresh=1` 时（刚保存完在新标签页打开的那种），标题与标签直接取自 URL，正文改走 GitHub API 读取，绕过 GitHub Pages 重新构建的延迟；读取失败再回退到静态文件。
- 评论区：**未实现**，暂留设计位。

### 新增 / 编辑文章页

- 顶部标签页：每个打开的文章一个标签（与 `blog_uuid` 绑定），切换标签保留各自的编辑状态；关闭、新建、离开页面前若有未保存修改会提示确认；右键支持固定、关闭、关闭右侧、关闭所有。
- 左侧文件栏，右侧资源栏，中间是表单。
- 新增：
  - 选择**分类**（可现场“新建分类”，不允许含 `/`）；
  - 填写**文件目录**（可多级，如 `底层/C++`，有历史目录补全；留空则用分类名作目录）；
  - 标题、正文、标签（chip 形式增删）、隐藏勾选。
- 编辑：`分类`、`标题` 不可为空；不改动已有文章的 `blog_uuid` 与文件路径。
- **保存不跳转**：点击保存时同步预开一个空白标签页（写上“正在保存…”）占住用户手势，提交成功后把该页替换成刚保存文章的 `fresh=1` 详情；提交失败则关闭该页。若浏览器仍拦截了新标签页，界面提示“保存成功，但新标签页被浏览器拦截，可从文章列表打开”。
- **提交信息可自定义**：表单底部的“提交信息”输入框，新增/编辑通用；留空时用默认的 `新增博客: <标题>` / `更新博客: <标题>`，占位符实时显示当前默认值；内容随标签页保留，提交成功后清空。

### 左侧文件栏（`blog/`）

- 树形展示 `blog/` 下所有 Markdown 文件；文件夹单击展开/收起（收起时子项一并隐藏），重新渲染后保持展开状态，打开文章会自动逐级展开所在目录。
- 每个文件行前有**显示状态勾选框**（对应 `hidden`）：勾选只登记到内存队列，行上出现待提交标记；点底部“**提交显示状态 (N)**”才一次性写回 `blog-config.json`。
- 文件夹右键：复制路径、新建子目录；文件右键：复制仓库内路径、打开文件。
- 双击文件：在编辑区打开，并加入顶部标签页。
- 顶部“新建”按钮用于在 `blog/` 下创建文件夹。

### 右侧资源栏（`media/`）

- 树形展示 `media/` 下全部资源；顶部有搜索框，实时过滤并按文件名自动展开命中路径。
- **上传**：先弹出窗口选择目标文件夹（可在弹窗内继续新建子文件夹），再选择本地文件；目标路径已有同名文件时拒绝并提示。上传内容只进待提交队列，不立即提交。
- **拖拽移动**：把资源文件拖到另一个文件夹上即可改归属路径；拖到资源树空白处 = 移回 `media` 根目录；拖回原目录 = 撤销这次登记。
- **重命名**：右键“重命名”只改文件名（不动所在目录），非法字符（`/ \ < > : " | ? *`）会被拒绝；改回原名即撤销。
- **删除**：右键删除只是登记到待删除队列，树上的条目先隐藏，真正删除发生在提交时。
- 以上四类改动（上传 / 待建文件夹 / 移动·重命名 / 删除）统一计入“**提交资源 (N)**”，N 是这四类的条目总和。点一次按钮产生且仅产生一条提交，提交信息形如 `提交资源: N 个文件`；**保存文章时也会顺带把这批队列一起提交**，不会分成两次。
- 提交内容的具体写法：
  - 上传文件：新增 blob；
  - 移动 / 重命名：新路径直接引用原文件的 blob SHA（旧路径写 `sha: null`），不重传内容；
  - 删除：路径写 `sha: null`；
  - 新建的空文件夹：用 `.gitkeep` 占位（目录里已有内容则不再写）。
- 队列只存在内存里，**刷新页面即丢弃全部未提交的登记**，需要重新操作。
- 双击资源文件：在浏览器新标签页打开其 `raw.githubusercontent.com` 原图地址。
- 待提交 / 已移动的文件行有底色与“待提交”小标，双击会提示“该文件的修改还没有提交，提交后才能在线查看”。

## 写仓库的机制

`assets/js/github-api.js` 里的 `CommitBatch` 负责所有写操作：

1. 把要写入的内容建成 blob；
2. 基于当前分支的最新 tree 生成新 tree（新增 / 替换条目、`sha: null` 表示删除）；
3. 建 commit；
4. 一次 PATCH 更新分支 ref。

任何一步失败都不会留下半成品提交。仓库内路径按“段”逐段 `encodeURIComponent`，所以中文目录、含空格的文件名都能正常读写。

## 数据格式（`blog-config.json`）

```json
{
  "browser_tag": "云风青的技术博客",
  "web_title": "云风青的技术博客",
  "web_introduction": "欢迎来到云风青的blog！这里分享技术心得和学习笔记",
  "web_icon": "assets/images/favicon.svg",
  "blogs": {
    "分类名": [
      {
        "blog_uuid": 20240606001,
        "title": "grpc测试",
        "description": "grpc测试",
        "path": "blog/grpc/grpc学习.md",
        "tags": ["RPC", "分布式", "后端"],
        "hidden": false
      }
    ]
  }
}
```

- `blogs` 的 key 就是首页的分类分组名；数组顺序即卡片顺序。
- `blog_uuid` 是文章身份标识（数字或 UUID 字符串都可以），编辑时不变。
- `path` 是仓库内真实路径，必须与 `blog/` 下的文件一致。
- `hidden` 可选，缺省视为不隐藏。

## 已知限制与待办

- 评论区未实现（原先设想过用 `comment/<blog_uuid>.json` 承载评论，涉及权限与黑名单策略，暂缓）。
- 详情页的“最新提交信息”和 `fresh=1` 正文都依赖 GitHub API：匿名额度（60 次/小时）用完时会显示为空或回退静态内容，不代表代码出错；登录后额度更高。
- 待提交队列不持久化，刷新即清空；也不支持跨标签页共享。
- 上传走 Contents/Trees API，适合中小文件；大文件建议直接 `git push`。
